# 気象・標高パッケージの読込（①）

ブラウザ計算用の気象・標高データを、1個の `.wasawx` ファイルとして交換できます。
読込機能自体はGFS取得・GRIB変換を行いません。新しいパッケージは[作成ツール（②）](BUILDER.md)で用意できます。同梱は従来の2026年9月10日の愛媛周辺fixtureです。

## 使い方

1. SETTINGSの「予測エンジン / API」で「ブラウザ内計算」を選びます。
2. 「使用中データをパッケージ保存」を押すと、同梱データを `weather-data.wasawx` として保存できます（約1.73MiB）。
3. 「気象・標高パッケージを読み込む」で、そのファイルを選びます。
4. 表示されたGFS run・対応日時・気象範囲・標高範囲を確認します。
5. 「パッケージのサンプル条件を入力」または手入力で条件を設定し、通常予測を実行します。
6. 元に戻す場合は「同梱の検証用データに戻す」を押します。

ファイルはサーバーへアップロードしません。選択したパッケージをメモリで保持し、外部飛行予測APIを使わず計算します。
読込時に予測条件は変更しません。サンプルは任意で、サンプルを含まないパッケージでは入力ボタンが無効になります。
同梱以外のサンプル条件は、Tawhiriとの一致検証済みとは限りません。

使用中のパッケージも再保存できます。予測履歴にはGFS run・気象/標高SHA-256に加え、読込ファイルのSHA-256を記録します。
既存の履歴と表示済みの結果はデータ切り替えで削除しません。

## 制限とエラー

- 1ファイル最大64MiB。未圧縮のバイナリ形式で、ZIPやGRIBを直接読み込むものではありません。
- 現在のエンジンと同じGFS 0.5度格子・47気圧面・連続する3時間間隔（0〜192 forecast hour）、15秒角の地表標高に対応します。
- 経度0〜360度の連続した矩形領域を扱います。気象格子の359.5度から0度への折返し、標高格子の継ぎ目をまたぐ領域は未対応です。
- 気象の最後の時刻・北端・東端は補間に次の格子点が必要なので利用できません。飛行終了まで範囲内に収まる必要があります。
- 通常予測・標準フライトのみです。大量予測への対応は追加していません。
- 形式・単位・格子・気圧面順序・容量・SHA-256・非有限値・高度の順序・標高欠損を検証します。
- 検証失敗時は使用中のデータとWorkerを保持します。計算中のデータ変更は受け付けません。
- SHA-256はファイルの同一性・破損検出用です。データ提供者や気象予測の正しさを保証する署名ではありません。

「このパッケージをこのブラウザに保存」を使うと、パッケージ本体をこのブラウザのIndexedDBに保存できます。ページ再読込後は使用中データが同梱データへ戻りますが、保存済み一覧から明示的に読み込めます。削除は保存済みコピーだけを消し、使用中データや既存の予測履歴は変えません。IndexedDBを無効にしているブラウザでは保存はページを閉じるまでの一時保持になります。自動ダウンロードは未実装です。
一度計算してWorkerを起動済みのページでは、同じデータによるオフライン再計算が可能です。
ページ再読込やデータ切り替え後のWorker初回起動には、アプリのモジュール取得が必要になることがあります。

## ファイル形式 v1（作成側向け）

| 順序 | 内容 |
|---|---|
| 先頭8バイト | ASCII `WASAWX01` |
| 次の4バイト | ヘッダーのバイト長（uint32 little endian） |
| ヘッダー | UTF-8 JSON、最大256KiB |
| 気象 | manifest.bytesバイト、Float32 little endian |
| 標高 | terrainMeta.bytesバイト、Int16 little endian |

ヘッダーは以下のフィールドを持ちます。

- `schemaVersion: 1`
- `engine: "tawhiri-0.2.0-js-phase0-v1"`
- `manifest`: [既存の気象メタデータ](fixtures/manifest.json)と同じ構造
- `terrainMeta`: [既存の標高メタデータ](fixtures/terrain.json)と同じ構造
- `sampleCase`: [既存の試験条件](fixtures/case.json)と同じ数値・日時フィールド、またはnull

manifest.file / terrainMeta.file / 出典URLは読込先として使用しません。外部ファイルを参照せず、内容はすべてパッケージ内で完結します。
気象配列の順序は `[forecast, pressure level, variable, latitude, longitude]`。
変数は `height, wind_u, wind_v`、単位は `gpm, m/s, m/s` です。

作成側では、共通の `js/pred/weather-package.js` をNode.jsからrequireし、
`encode({manifest, terrainMeta, weatherBuffer, terrainBuffer, sampleCase})` でパッケージを生成できます。
入力バッファはArrayBufferです。読込・検証は同じモジュールの `decode(arrayBuffer)` を使います。
GFS取得・切り出し・変換からこの形式を作る処理は[作成ツール（②）](BUILDER.md)で利用できます。

## 検証の意味

同梱パッケージの保存→読込→実Worker予測で、既存Tawhiri基準の着地点が変わらないことを検証しています。
日時・地域をずらした合成メタデータのテストは、パッケージの範囲が計算へ渡ることの検証です。
別日時・地域の実GFSを取得した検証ではありません。
検証結果: 構文チェック63ファイル、Nodeテスト154件、Chromiumブラウザテスト26件が成功しました。
既存API・モバイル・PWAの回帰テストを含みます。GitHub Pagesへの公開は行っていません。

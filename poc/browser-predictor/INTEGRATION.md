# 通常予測への試験接続

固定fixtureによるブラウザ計算を、2026版の通常予測に接続しています。
最新の気象データによる運用機能ではありません。元の独立PoCと数値計算モジュールは維持しています。

## 試し方

1. リポジトリのルートで Node.js 20以上を使い、`node cors-proxy.js` を実行します。
2. http://localhost:3100 を開きます。
3. SETTINGSの「予測エンジン / API」で「ブラウザ内計算」を選びます。
4. 「検証済みの試験条件を入力」を押します。
5. 通常の予測実行ボタンを押します。RESULTSで地図・履歴・CSV/KML出力を確認できます。

ブラウザ試験にはDocker、Tawhiriサーバー、外部飛行予測APIは不要です。
GitHub Pagesのプロジェクト配下でも同じ相対パスで動作する構成です。
公開時は既存PoCのモジュールとfixturesも一緒に配信してください。今回は公開操作を行っていません。

## データパッケージ

気象と標高を1個のファイルとして保存・読込できるようになりました。
[パッケージの使い方と形式](PACKAGES.md) を参照してください。
読み込んだデータの日時・地域が予測に使用されます。以下は同梱データの範囲です。

## 対応範囲

- 標準フライトの通常予測、愛媛13条件、自動探索、不確実性解析（Monte Carlo / LHS / Sobol）に対応します。落下のみ・時間別は未対応です。
- GFS run: 2026-09-10 00:00 UTC。forecast hours: 3 / 6 / 9。
- 有効時刻: 2026年9月10日12:00〜18:00 JST未満。着地までデータ内に収まる必要があります。
- 気象: 北緯30〜36°・東経128〜137°。地表標高: 北緯32〜35°・東経131〜135°。
- 放球高度は海抜高度です。入力値がブラウザ用DEMの地表以下でも入力欄は変更せず、計算開始点だけをDEM地表へ自動的に合わせます。
- 時間・地域のデータ不足、破損、読み込み失敗はエラーで停止します。SondeHub等へ自動切り替えしません。

標準の試験条件は北緯33.13492°・東経132.50477°、海抜100m、
2026年9月10日13:30 JST、上昇5m/s・海面下降5m/s・破裂30,000mです。
Tawhiriとの数値一致は実際の気球に対する予測精度を保証しません。

## 構造

```text
既存の通常予測UI
  → PredictionRunner / PredictionRequestContext
  → BrowserPredictor provider
      → 同梱fixtureまたは選択したパッケージを読み込み・検証
      → 端末性能・データ容量・同時要求数に応じた1〜4個のDedicated Web Worker
      → 元PoCの補間・標準大気・RK4・地表交差計算
  → Tawhiri形式の結果
  → 既存の地図・グラフ・履歴・CSV/KML
```

接続先IDは `browser-fixture` です。通常のHTTPクライアントでは扱わず、
RequestContextがブラウザproviderを選びます。PredictionRunnerの計算結果の正規化は変更していません。
既存のSondeHub / Localhost / Customの経路と並列数は維持しています。

履歴には時刻付き軌跡、上昇/下降の区分、固定データ識別子、GFS run、
気象・標高のSHA-256を保存します。HTTP試行数は0、ブラウザ計算数は別に記録します。
CSV/KMLは取得済みの結果から作成し、APIのダウンロードURLにはアクセスしません。

## データ保持とオフライン

気象・標高のバイナリは合計約1.72MiBです。最初のブラウザ予測で1回読み込みます。
通常予測は1 Workerだけを作り、複数計算時に必要な分だけ2〜4 Workerへ増やします。
各Workerへのデータ複製は必要ですが、遅延生成により単一予測での複製を避けます。
一度計算したページを開いたままなら、ネットワーク切断後も再計算できます。
ページの再読み込みを伴う完全オフライン利用は今回の対象外です。

「このパッケージをこのブラウザに保存」で、選択中の気象・標高パッケージをIndexedDBへ明示保存できます。再読込後は保存済み一覧から選んで読み込みます。保存容量はブラウザごとの上限に従います。
PoC配下はPWAの自動キャッシュから除外し、アプリシェル更新時の一括取得を防ぎます。
通常の実行履歴は既存のIndexedDBへ保存します。

## GitHub Pages向けデータ作成ツール

設定欄の「気象データ作成ツールをダウンロード」からZIPを取得できます。
ZIPを展開して `start-weather-builder.bat` をダブルクリックし、地域GFSから `.wasawx` を作成します。
ブラウザ自身がbatを実行することはできません。Weather BuilderにはNode.js 20.3以上とDocker Desktopが必要です。
配布ZIPは `npm run build:weather-builder-package` で再現生成します。

- 範囲外・未対応モード・データ欠落のエラーと再試行
- GitHub Pages相当のサブパス配信
- ブラウザ試験後にSondeHub / Localhost / Customへ切り替えたときの接続先・出力リンク
- 固定データ破損の検知、中断・タイムアウト時のWorker停止
- 既存のPWAシェルに固定fixtureが保存されないこと

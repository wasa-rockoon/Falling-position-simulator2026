# Falling Position Simulator 2026

高高度気球の放球条件から飛行経路と着地点を予測し、地図・比較表・統計で放球計画を支援するWASA向けブラウザアプリです。通常予測、愛媛向け13条件比較、自動探索、気球ガス計算、不確実性解析を一つの画面で扱います。

> [!IMPORTANT]
> 本アプリの予測、海陸判定、気象評価は放球・回収計画の検討を補助するものです。実施判断では最新の気象情報、航空・海上の規制、現地状況、運用手順を別途確認してください。

## プロジェクト状況

現在は `dev/kotaki` で次期機能を統合中です。通常予測を維持しながら、自動探索、ガス計算、不確実性解析、API呼出制御、PWA資産を追加しています。機能の整理と画面構成の再設計はPhase 0以降の計画で管理します。

## 主な機能

- Tawhiri / SondeHubによる上昇・破裂・下降経路の予測
- BASE + 12変動条件による愛媛向け13条件比較
- 地点・時間帯を横断する自動探索
  - 高速: 粗探索で不合格候補を除外
  - 全件精査: 粗探索では除外せず全候補を13条件評価
  - ランキング: 除外せず有望候補から評価
- KMLを正本とした漁船・支援地点22件、実回収地点8件
- 2025年版ガス計算シートに基づくガス量・ボンベ本数・破裂高度計算
- Monte Carlo / Latin Hypercube / Sobol と正規分布 / Weibull分布による不確実性解析
- API呼出上限、概算時間、キュー、間隔制御、再試行、3時間キャッシュ
- 実行中ジョブの「現在の1件完了後」中断、再読込後の再開、CSV再出力
- PWAインストール、アプリシェルと表示済み地図タイルのオフライン利用

| 利用場面 | 主な機能 |
|---|---|
| 1条件を確認 | 通常予測、飛行経路、高度・風速グラフ、CSV/KML |
| 条件差を比較 | 愛媛向け13条件比較、着地点範囲、一覧出力 |
| 放球候補を探す | 複数地点・時間帯の自動探索、条件判定、ランキング |
| 計画の余裕を見る | 不確実性解析、確率楕円、密度等高線、海上率信頼区間 |
| 放球条件を作る | ガス量、ボンベ本数、上昇速度、破裂高度の計算 |

## クイックスタート

必要環境はNode.js 20以上です。npmの実行時依存はありません。

```powershell
node cors-proxy.js
```

[http://localhost:3100/](http://localhost:3100/) を開きます。静的配信元とローカルTawhiriの接続先は [http://localhost:3100/__server-info](http://localhost:3100/__server-info) で確認できます。

ローカルAPIを選ぶ場合、既定では `localhost:8000` にTawhiriが必要です。

```powershell
$env:TAWHIRI_HOST = 'localhost'
$env:TAWHIRI_PORT = '8000'
$env:PORT = '3100'
node cors-proxy.js
```

Tawhiriをローカルで起動しない場合は、画面のAPI接続先でSondeHubを選択してください。ローカルAPI選択中に `502` になる場合は、まず8000番ポートのTawhiri起動状態を確認します。

変更後の確認は次の3コマンドを基準にします。

```powershell
npm run build
npm run check
npm test
```

## 生成される資産

`npm run build` は次を再生成します。

1. `漁船・回収地点位置関係マップ.kml` から `ports.json`
2. 192px / 512px PWAアイコン
3. jQuery UI画像スプライト
4. 実際のHTML依存を列挙した `sw.js`

`npm run check` はNode標準の構文検査を使います。Acornや `node_modules/` は不要です。自動テストはAPIクライアント、自動探索、ガス計算、不確実性解析、KMLデータ分離、PWA資産、依存ハッシュ、初期化経路を対象にしています。ブラウザ統合動作は[手動確認チェックリスト](docs/MANUAL_CHECKLIST.md)で確認します。

## 自動探索の判定

- 海上率は下限値以上で合格
- 距離・降水・風速などの上限条件は上限値以下で合格
- 天候値を取得できない候補は、その理由だけでは除外しない
- 全件精査とランキングでは粗探索不合格を最終除外に使わない
- 開始前に最大API試行数と概算時間を表示し、設定上限を超えて新しいHTTP試行を開始しない
- 中断要求は進行中の候補またはAPI呼出を完了した境界で反映する

## ガス計算

同梱計算ロジックは、プロジェクト外の以下の資料を読み取って実装しています。

- `ガス計算シート2025年版.xlsx`
- `【解説書】気球ガス計算シート.pptx`

既定値では必要ガス量約9.4565 m³、断熱補正ボンベ本数約1.5753本を再現します。6方式の破裂高度推定、ボンベ残圧・不足表示、上昇速度と推奨破裂高度の予測フォーム反映に対応します。元資料で係数未定義の1200g気球は推測値を作らず未定義と表示します。

## 状態とAPI安全性

- 通常フォームの前回値・プリセット: localStorage
- 保存した放球地点: Cookie（既存互換）
- テーマ・サイドバー・ガス設定・愛媛履歴: localStorage
- API応答: メモリ + IndexedDB、3時間TTL
- 自動探索・不確実性解析ジョブ: IndexedDB
- 実行中の地図レイヤー: ページ内メモリ

API URLは実行ごとの設定として固定し、非同期処理中に共有URLを書き換えません。同一リクエストは統合し、キュー・再試行・中断・HTTP試行予算を共通APIクライアントで管理します。

## データと依存関係

`ports.json` は手編集せず、KML修正後に `npm run build:data` で再生成します。探索距離には支援地点だけを使い、実回収地点は実績表示用として分離しています。

ブラウザ依存はローカル同梱し、バージョン・ライセンス・SHA-256を `vendor-dependencies.json` に記録しています。未使用だったTurf、Leaflet Heat、jQuery Formの実行時読込はありません。

外部通信先は、Tawhiri/SondeHub（飛行予測）、Open-Meteo（気象）、BigDataCloudとOverpass（沿岸・内水面の補助判定）、地図タイルです。APIキーや秘密情報をソースへ保存しないでください。

`node_modules/`、Acorn、生成CSV、解析用一時ファイルは `.gitignore` 対象です。

## 構成

- `index.html`: 画面の静的骨格
- `js/core/`: 保存、通知、中央初期化、PWA登録
- `js/pred/pred-api-client.js`: APIキュー・再試行・キャッシュ・試行予算
- `js/pred/pred-job-store.js`: 中断・再開用ジョブ保存
- `js/pred/auto-search*.js`: 自動探索
- `js/pred/uncertainty-*.js`: 不確実性解析
- `js/calc/balloon-gas.js`: ガス計算の純粋ロジック
- `js/pred/pred-new.js`: 既存通常予測・愛媛13条件・地図描画との互換接続
- `scripts/`: KML、アイコン、Service Workerの再生成
- `tests/`: Node標準テスト

画面初期化は `AppShell.registerInitializer()` に集約し、各機能を優先度順に一度だけ起動します。

## 既知の制約

- 新しい予測や気象取得にはネットワークまたは起動済みローカルTawhiriが必要
- 海陸判定は同梱GeoJSONを基本に外部APIを補助利用するため、沿岸・内水面では通信状態とデータ精度の影響を受ける
- 通常予測と愛媛向け既存描画エンジンは互換性維持のため `pred-new.js` に残っている
- ブラウザE2Eは手動チェックリストで確認する

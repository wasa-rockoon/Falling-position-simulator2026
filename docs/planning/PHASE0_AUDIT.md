# Phase 0: 機能・情報設計監査

- 完了日: 2026-08-14
- 対象基準点: `62de923`
- 状態: 完了
- 方針: Phase 0では動作を変更せず、残す機能、統合する機能、データ契約、実装順を固定する。

## 目的と利用者

このアプリの中心目的は「高高度気球を、許容できるAPI負荷で、安全に回収しやすい条件へ放球するための判断材料を作ること」です。

主な利用者の作業は次の5つです。

1. 1条件の飛行経路と着地点を確認する。
2. 上昇・下降・破裂条件の差が着地点へ与える影響を比較する。
3. 複数地点・時間帯から有望な放球候補を探索する。
4. ガス量、上昇速度、破裂高度を整合させる。
5. 不確実性を含む着地点分布、海上率、回収可能性を評価する。

## 基準点

Phase 0開始時点で、次が実装済みです。

- 通常予測と愛媛向け13条件比較
- 高速、全件精査、ランキングの3方式による自動探索
- 実行前の最大HTTP試行数と概算時間、APIキュー、再試行、キャッシュ
- 「現在の1件完了後」の中断、IndexedDBへの自動保存、再開
- 2025年版資料に基づくガス・破裂高度計算
- 不確実性解析、95%確率楕円、密度50/80/95%等高線
- 中央初期化、通知、PWA生成、54件のNode自動テスト

## RESULTSの情報設計

RESULTSは機能ごとの出力を継ぎ足す場所ではなく、共通の実行結果を読む場所にします。

| 領域 | 内容 |
|---|---|
| 概要 | 実行状態、日時・地点、主要着地点、海上率、回収距離、警告、主要操作 |
| 比較・グラフ | 地図レイヤー選択、高度、風速、Variant比較、不確実性分布 |
| 履歴 | 種別・状態・日時による検索、再表示、再実行、再開、CSV/KML出力、削除 |
| 診断 | API試行、キャッシュ、待ち行列、警告、エラー、実行コンテキスト。SETTINGS外の常設入口から開く |

操作の優先度を次に統一します。

- Primary: `予測を実行` またはモーダル内の `解析を開始`
- Secondary: `放球自動探索`、`ガス・破裂高度計算`、`不確実性解析`
- Tertiary: `CSV出力`、`KML出力`、`地図で表示`、`設定を反映`
- Destructive: `履歴を削除`。確認を必須にし、通常操作から距離を置く

候補一覧や履歴はパネル高を制限して内部スクロールさせ、モーダル全体が画面外へはみ出さないようにします。ボタンの高さ、角丸、色、アイコン、無効・実行中状態は共通コンポーネントへ統一します。

## 高度・風速グラフ

- 未実行時は白紙キャンバスを出さず、「予測後に表示されます」と次の操作を示す。
- 通常予測は現在のRunを既定表示する。
- 愛媛モードはBASEを既定表示し、Variantを複数選択して重ねられる。
- 履歴から最大5系列を比較対象へ追加できる。
- 色は地図軌跡、表、凡例、グラフで同じ系列色を使う。
- 軸、単位、JST/UTC、欠損値の扱いを共通化する。

## 現在の海陸判定

現時点では判定経路が統一されていません。

1. `js/pred/landsea.js` が日本域GeoJSONを読み込み、point-in-polygonで同期判定する。
2. 通常予測の一部は `classifyLandSeaAt()` を通り、沿岸付近をランダムサンプリングする。
3. 曖昧な地点ではBigDataCloudの逆ジオコーディングを使う。
4. ローカルで陸と判断した地点はOverpassで内水面を確認する場合がある。
5. 自動探索、不確実性解析、愛媛モードの一部は外部補助を通らず、`LandSea.isLand()` を直接使う。

このため、BigDataCloudとOverpassは現在も使われています。ただし、精度は定量評価されておらず、以下の問題があります。

- GeoJSONのPolygon/MultiPolygonで外周リングだけを見ており、穴と内水面を完全には扱わない。
- 沿岸サンプリングが乱数なので、同じ地点でも経路によって結果が変わり得る。
- 海岸距離を度数×111kmで近似し、経度方向の縮尺差を考慮していない。
- 機能ごとに判定経路が違い、同一地点の結果が一致しない可能性がある。
- 外部APIの失敗、レート制限、名称ヒューリスティックを明示的な `unknown` として保持していない。
- 大量探索で外部判定を使うと、予測APIとは別に通信量と障害点が増える。

## 海陸判定の決定

- 大量探索の最終判定は、バージョン固定したローカルデータによる決定論的分類を標準にする。
- Polygonの穴、MultiPolygon、内水面を正しく扱う。
- 距離計算は地球上の距離として計算し、単純な度数換算を廃止する。
- 結果は `land`、`sea`、`inland_water`、`unknown` の4値とし、判定元、信頼度、海岸距離、データ版を保存する。
- BigDataCloud/Overpassは既定の大量処理から外し、詳細確認用の任意フォールバックに限定する。
- 外部通信失敗を海または陸へ置き換えない。
- 海上率は `sea / 判定済みサンプル` とし、unknown率を別表示する。unknownを含む候補は「合格」ではなく「要確認」にする。
- 四国・九州・中国地方、島、港湾、河川・湖沼を含む固定検証地点を作り、データ更新時に回帰試験する。

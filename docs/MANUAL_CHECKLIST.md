# 手動確認チェックリスト

自動試験で再現できない実API、実端末、予測妥当性をリリース前に確認します。実行日、担当者、ブラウザ、API接続先、結果をリリース記録へ残してください。

## 公開ページの確認

GitHub Pagesを公開したら、公開URLを別ブラウザまたはシークレットウィンドウで確認します。

- HTTPSの公開URLで画面、地図、SETTINGS、RESULTS、履歴が開く。
- Consoleに同一オリジン資産404やService Worker登録失敗がない。
- 公開ページではSondeHub (Public)で通常予測を1件だけ実行する。
- 公開ページではLocalhost (Docker)を使わない。これは開発・現地PC専用であり、cors-proxy.jsとローカルTawhiriはGitHub Pagesで動かない。
- 公開後にdev/kotakiからmasterへ切り替える場合、同じURLで新しい版が表示されることを確認する。

## 0. 自動確認

```powershell
npm ci
npm run build
npm test
npm run test:e2e
```

- 全コマンドが終了コード0になる。
- `git diff --exit-code -- ports.json sw.js` で未コミット生成差分がない。
- Consoleに未処理例外、同一オリジン資産404、重複IDがない。
- Playwrightは公開Tawhiri/Open-Meteoへ通信せず固定APIで完了する。

## 1. 起動と基本表示

- `node cors-proxy.js` 後、起動ログのURLを開ける。
- `/__server-info` の `staticDir` がこのプロジェクトを指す。
- 地図、SETTINGS、RESULTS、診断、テーマ、サイドバー開閉が操作できる。
- SETTINGSを開いていなくても上部の「診断」からログを表示できる。
- RESULTSが「概要」「グラフ」「履歴・出力」に分かれ、内容が重ならない。
- 予測前の高度・風速グラフに空状態の説明が表示され、真っ白にならない。

## 2. 通常予測

- GitHub PagesではSondeHubを選ぶ。起動済みLocalhostはnode cors-proxy.jsで開いた現地PCの画面だけで選ぶ。
- 現在から公開API許容範囲内のJST日時、地点、高度、上昇、下降、破裂高度を入力する。
- 「予測を実行」で軌跡、離陸、破裂、着地点が地図に表示される。
- RESULTS概要に到達距離、飛行時間、着地点、海陸、地上・最大風速が表示される。
- 高度・風速グラフに系列が追加される。
- CSV、KML、URL共有、画像出力が操作できる。
- `Illegal invocation`、`requestContext is not defined` が表示されない。
- API接続先が実行中に勝手に変わらない。

## 3. 愛媛13条件

- 予測タイプを「愛媛気球実験用」にして実行する。
- 13/13が完了し、BASE、単一変化6、二変数変化6が表示される。
- 平均着地点、最大偏差、陸上率・海上率、各条件の海陸判定が更新される。
- 地図上の13着地点とBASE軌跡、最大5系列のグラフを切り替えられる。
- 愛媛CSV、JSON、着地範囲の表示が操作できる。
- 旧履歴を削除せず、共通履歴にも愛媛13条件として保存される。

## 4. 放球自動探索

- 開始前に候補数、論理API要求、再試行込み最悪HTTP試行、上限、概算時間が表示される。
- 海上率は入力した下限と等しい候補も合格する。
- 雨量・風速・沖合距離は上限と等しい候補も通る。
- 高速モードでは粗探索不合格を精密探索から除外する。
- 全候補精密モードでは粗探索不合格も13条件へ進む。
- 段階的モードでは除外せず見込み順に進む。
- 公開APIで300試行を超える設定に警告が出る。
- 「中断」で現在候補を完了して止まり、次候補へ進まない。
- 再開後に同じ候補を重複保存しない。
- 候補完了ごとに自動保存され、再読込後も再開できる。
- HTTP上限到達時は一部完了になり、上限を増やして続行できる。
- 完了時のCSV自動保存を維持し、結果欄の「CSV出力」でも任意保存できる。
- 大量候補の結果一覧がモーダル外へはみ出さず、内部スクロールできる。

## 5. ガス・破裂高度計算

- SETTINGSの「ガス・破裂高度計算」からモーダルを開ける。
- 通常モードと検証用モードを切り替えられ、入力値が再読み込み後も自動復元される。
- 1000 / 1500 / 2000 / 3000 gを選択でき、1200 gは表示されない。
- 4本それぞれの容積・初期圧力を変更できる。
- 準静的、ポリトロープ、断熱の3過程と各ボンベの残圧が表示される。
- 破裂高度は4方式表示され、初期状態では球近似・直径が選択される。
- 判定方式を変更すると選択行と破裂高度表示が切り替わり、「予測条件へ反映」で上昇速度と選択した破裂高度がSETTINGSへ入る。
- モバイルでも画面外へはみ出さず、Escapeまたは閉じるボタンで閉じられる。
## 6. 不確実性解析

- 解析画面でJST日付・時刻を入力でき、「SETTINGSの日時を読込」で一致する。
- 現在地点と登録地点を選べる。
- モンテカルロ、Latin Hypercube、Sobolと正規・Weibullを選べる。
- シードを同じにすると同じ入力サンプルになる。
- 地点数、最小/最大サンプル、HTTP上限、概算時間が表示される。
- 地点をラウンドロビンで進め、1地点の3連続エラーが他地点を止めない。
- HTTP再試行を含め設定上限を超えない。
- 現在のAPI呼出完了後に中断し、再読込後も再開できる。
- 海上率95%信頼区間、平均着地点、95%確率楕円の長軸×短軸と角度が表示される。
- 着地点、95%楕円、密度50/80/95%等高線を独立に重ねられる。
- 8点未満では密度等高線を計算しない。
- CSVを出力できる。

## 7. 履歴・自動保存

- SETTINGSの前回値と名前付きプリセットが再読込後も復元される。
- 通常、愛媛、自動探索、不確実性解析が共通履歴へ種類付きで並ぶ。
- 種類フィルターと固定/解除が動き、保存・削除時に一覧が自動更新される。
- 「地図表示」で保存済み軌跡・着地点を重ねられ、同じボタンの「地図から消す」で解除できる。
- 地図表示中の履歴を削除すると、その履歴の地図表示も同時に消える。
- 旧愛媛履歴は共通履歴へ互換移行され、重複した旧履歴欄を表示しない。
- 各履歴のCSVを出力でき、軌跡・着地点を持つ履歴ではKMLも出力できる。
- 「再実行準備」で入力だけがSETTINGSへ戻り、自動実行しない。
- 実行中履歴は削除できず、完了履歴は二段階確認で削除できる。
- 「表示クリア」は地図・グラフだけを消し、保存履歴と自動保存設定を消さない。

## 8. 海陸・支援地点

- 既知固定点で本州/四国がland、瀬戸内海/太平洋がsea、琵琶湖がinland_waterになる。
- 内水面を海上率へ含めない。
- unknownを陸または海へ自動変換しない。
- 同じ座標を繰り返して同じデータ版・分類になる。
- 実行中にBigDataCloud/Overpass通信がない。
- 最寄り支援地点と距離、回収実績の有無が表示される。
- KMLの支援地点と実回収地点が用途別に保たれる。

## 9. モバイル・キーボード・アクセシビリティ

1366×768と幅390px前後で確認します。

- 主要ボタンが同じ見た目・間隔で並び、横スクロールを強制しない。
- 自動探索と不確実性解析のダイアログが画面内に収まり、内部スクロールできる。
- 各ダイアログに名前付き `role=dialog` があり、開いた後に最初の入力へフォーカスする。
- Escで閉じ、起動ボタンへフォーカスが戻る。
- RESULTS内タブは左右矢印で移動でき、選択状態が読み上げ可能である。
- 診断パネル、トースト、進捗に適切なlive region/状態がある。
- マウスなしで予測、各ダイアログ、履歴操作へ到達できる。

## 10. PWA・オフライン・更新

- manifestの言語、scope、192/512pxアイコンが正しい。
- 初回オンライン起動後、Service Workerがactivatedになる。
- アプリキャッシュは現行版1件、タイルキャッシュは最大1件の名前に整理される。
- 更新通知の「今すぐ更新」で一度だけ再読込し、無限更新しない。
- Offlineへ切り替えて再読込してもアプリシェルと保存履歴が開く。
- オフラインの新規予測は成功扱いにならず、通信エラーが明示される。
- 表示済みタイルは使えるが、未表示タイルを保証しない。

## 11. 診断と安全性

- 429、5xx、タイムアウト、オフラインを利用者向けメッセージと診断へ分離する。
- 診断にAPIキー、token、secret、Bearer値が残らない。
- 長大な応答本文やError causeを履歴へ保存しない。
- 技術メッセージが上限で切り詰められる。
- CSV、履歴、URL共有に意図しない秘密情報がない。

## 12. 実APIの最終確認

自動E2Eは予測精度や外部サービスの可用性を保証しません。GitHub PagesではSondeHub、現地PCではSondeHubまたは起動済みLocalhostを使い、少なくとも次を実APIで確認します。

- SondeHubで通常予測1件
- 起動済みLocalhostで通常予測1件
- SondeHubまたはLocalhostで愛媛13条件1件
- Open-Meteoを使う短時間・1地点の自動探索
- 実API4〜8サンプルの不確実性解析
- 予測軌跡と既知の気象・地理条件に明らかな矛盾がないこと

確認できない外部サービスがある場合は、未確認項目、理由、影響範囲をリリース記録へ明記します。
